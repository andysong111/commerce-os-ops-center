# 샵플링 주문·송장 자동화 개발 계획

## 목표

평일 12시 31분에 주문·클레임·문의 수집부터 신규주문 매핑, 발송준비, 택배사 전송, 송장 출력까지 실행한다. 포장 후에는 사용자가 촬영한 남은 송장 사진을 기준으로 미발송 주문을 식별하고, 검토를 거쳐 송장번호 삭제와 필요한 상품의 품절처리를 수행한다.

## 확인된 운영 규칙

- 남은 송장 사진은 포장 완료된 주문이 아니라 포장하지 못한 주문을 뜻한다.
- B5 매핑은 이미 연결된 상품을 우선 사용한다.
- 신규 매핑 검색은 별도로 확인된 B코드(옵션자체관리코드)를 최우선으로 하고, 모델번호, 쇼핑몰 상품코드 순으로 조회한다. `자사코드(site)`는 임의 값이므로 B코드로 간주하거나 검색에 사용하지 않는다. B5 주문 행에 B코드나 모델번호가 없으면 상품명에서 추측하지 않는다.
- 기본 매핑수량은 1이며 상품명에 `1+1`, `2개입`, `10개입` 등이 명시된 경우만 구성수량에 맞춘다.
- 주문수량은 매핑수량과 별개다.
- 옵션상품은 주문 옵션명과 샵플링 옵션명을 일치시킨다.
- 동일 B코드 상품이 여러 개면 어느 항목을 선택해도 된다.
- 쪼개기 상품은 상품명과 B코드를 확인하고, 동일 상품이 여러 개면 묶음 등록 상품을 우선한다.
- B7은 오늘 생성된 신규주문을 1000개 조회한 뒤 일괄 발송준비로 변경한다.
- B12 자동합포장은 `우편번호 + 주소 + 수취인 + 전화번호 + 쇼핑몰명` 조건을 사용한다.
- 택배사는 도소매사우루스이며, 전송완료 건을 B코드 오름차순과 수량 오름차순으로 출력한다.
- 출력은 Xprinter XP-DT108B의 대한통운 송장 용지, 세로 방향, 여백 맞춤, 배율 100을 사용한다.
- 운영 출력은 Chrome 기본 인쇄창을 제어하지 않고 검증된 PDF를 Windows 스풀러에 직접 전달한다.

## 단계별 개발

### 0. 주문수집부터 송장출력까지 일일 통합 흐름

상태: 단일 명령 구현 완료. 주문·클레임·문의 수집부터 B5 매핑, B7 발송준비, B12 자동합포장·택배사 전송, B코드·수량 오름차순 정렬, Xprinter 종이 출력까지 실제 배치로 완주했으며 사용자가 송장 크기와 순서를 확인했다. 다음 단계는 매핑 예외 축적과 평일 예약 실행 활성화다.

- B1에서 주문·클레임·문의 수집 3개 작업을 모두 실행하고 각 진행창 완료를 대기
- B5에서 미매핑 주문이 있으면 체크포인트를 남기고 사용자 검토 요청, 없으면 매핑완료·신규주문확정 일괄 처리
- B7에서 오늘 생성된 신규주문을 1000개 조회하고 발송준비로 변경한 뒤 신규주문 0건 재검증
- B12에서 오늘 수집분을 1000개 조회하고 네 번째 자동합포장 조건을 적용한 뒤 도소매사우루스로 전송
- 전송한 정확한 주문 집합만 택배사전송완료에서 B코드·수량 오름차순으로 선택
- 송장 HTML의 실제 페이지 수를 자동 검출하고 Xprinter 전용 용지·크기·페이지 수를 검증한 뒤 직접 출력
- 날짜별 체크포인트로 매핑 검토 후 `--resume` 가능
- 기본 명령은 외부 변경 없는 드라이런이며 `--execute`에서만 상태 변경·전송·출력 실행

### 1. 남은 송장 식별 기반

상태: 구현 및 로컬 검증 완료.

- B12에서 운송장번호, 샵플링 주문번호, 상품, 수량만 읽는 읽기 전용 매니페스트 캡처
- 수취인명, 전화번호, 주소 미수집
- 로컬 Tesseract OCR로 사진의 12자리 운송장 후보 추출
- 캡처 목록과 정확 일치한 번호만 미발송 후보로 인정
- 합포장 송장 한 장에 여러 샵플링 주문이 연결된 경우 함께 보존
- 중복 사진, 알 수 없는 번호, 송장 수 불일치, 다중 번호는 자동 차단
- 현재는 `DRY_RUN`이며 외부 변경 불가
- B12 캡처부터 API 식별, 사진 OCR, 합포장 대조까지 한 명령으로 실행하는 읽기 전용 검토 흐름 제공

### 2. B코드 확정과 검토 화면

상태: 정확 ID 기반 해석기와 최소필드 API 공급 단계 구현 완료. 로컬 API 인증 설정 후 실조회 검증 필요.

- 샵플링 주문의 상품·옵션 ID로 정확한 B코드 조회
- 상품명 유사도는 사용하지 않으며 상품 또는 옵션 후보가 복수이면 자동 차단
- 품절 사유 사진에만 B코드 품절 후보 생성
- 한 합포장에 여러 B코드가 있으면 사용자가 품절 대상을 선택
- 실행 전 주문번호, 송장번호, 상품, 수량, 조치 사유를 한 화면에서 검토

### 3. 송장번호 삭제 및 품절 실행

상태: B12 삭제 화면과 확인창 학습 완료. 정확 집합 검증, 확인창 처리, 삭제 후 양방향 재조회 실행기까지 구현 및 로컬 검증 완료. 실제 실행은 한 건별 정확한 승인키가 있어야만 열림.

- B12에서 정확한 송장번호와 연결 주문 전체를 다시 확인하고 해당 행만 선택
- `송장번호 삭제` 클릭 후 `삭제 후 복구 불가`와 `택배사 전송대기` 전환 문구가 모두 일치하는 확인창만 승인
- 일반 Chrome의 CDP 이벤트로 확인창을 처리하며 코덱스 내부 브라우저의 팝업 표시에 의존하지 않음
- 삭제 후 송장번호가 비었고 상태가 `택배사 전송대기`인지 다시 조회하여 검증
- 같은 명령을 재실행하면 이미 삭제된 주문이 전송대기에 있는지 확인만 하고 삭제를 반복하지 않음
- 품절 주문에 한해 정확한 B코드를 품절처리
- 작업별 전후 상태, 시각, 결과를 감사 로그에 기록
- 부분 실패 시 다음 단계로 진행하지 않고 사용자에게 알림
- 송장 API는 삭제를 보장하지 않으므로 삭제는 B12 UI로만 수행
- 일반 Chrome에서 실제 B12 삭제 1건과 전송대기 전환을 확인했으며, 자동 실행기는 다음 실주문에서 먼저 드라이런으로 화면 적합성을 검증

### 4. 쇼핑몰 송장전송

상태: 3단계 이후.

- 미발송 송장 삭제 확인 후 남은 주문만 쇼핑몰로 송장전송
- 전송 대상 건수와 성공·실패 건수를 대조
- 이미 전송된 주문의 중복 전송 방지

### 5. 문의·클레임과 CJ 수거

상태: 최근 31일 읽기 전용 수집, 안전 필터, 검토 계획, B13 답변 팝업 자동 저장, 정확한 1건 최종 전송 및 API 재검증 실행기까지 구현하고 로컬 검증 완료. 문의 수집은 별도 예약을 만들지 않고 평일 12시 31분 주문·클레임·문의 통합 수집만 사용한다. 승인 필요 답변은 `[초안]` 표지를 붙여 B13에 저장하고 샵플링에서 직접 검토하며, 표지가 남은 동안 쇼핑몰 전송은 차단한다. CJ 반품 수거는 로그인 복구, 건별접수 자동 이동, 원송장 조회, 감독 저장, 신규·기존 접수 증거 확인, 샵플링 B7 상태변경과 중단 후 재개까지 구현하고 실제 1건 운영 검증을 완료했다. 다음 영업일 반품운송장 조회와 샵플링 C/S 메모 기록도 구현했으며 실제 번호 생성 후 운영 검증만 남아 있다. 교환 재발송 학습은 남아 있다.

- B13 문의답변관리와 API에서 미답변 문의를 조회하고, 문의키·상품·유형·내용 지문만 검토 계획에 보존
- 문의 원문이나 제목이 바뀌면 기존 답변 초안을 폐기한다. 승인 필요 답변은 `[초안]`을 정확히 한 번 붙여 B13에 저장하고 API에서 동일 본문과 `전송대기` 상태를 재확인한다.
- 2025-10-03~2025-10-23 B13 이력 24건은 문체와 문의 유형을 파악하는 참고 자료로만 사용한다. 과거 답변을 그대로 자동 재사용하지 않는다.
- 해당 이력은 배송·출고·송장 11건, 반품·환불·회수 12건, 상품정보 1건으로 구성되어 운영 상태 조회가 답변 품질의 핵심임을 확인했다.
- `확인`, `확인하였습니다`, `네 확인드리겠습니다`처럼 처리 내용이 없는 확인성 답변은 자동 전송하지 않는다.
- 배송·송장 답변은 현재 주문/운송장 상태, 반품·환불 답변은 현재 클레임/수거 상태를 확인한 뒤 작성한다. KC·인증·법령 소명 및 반품 불가 단정은 증빙을 확인한 수동 검토 건으로 남긴다.
- `[초안]` 답변은 별도 승인 화면 없이 B13에서 직접 확인한다. `[초안]`이 남은 답변은 수동·자동 승인키가 있어도 전송하지 않는다. 최종 문구가 확정되어 표지가 제거된 뒤에만 `선택된 문의를 쇼핑몰로 전송하시겠습니까?` 확인 절차와 완료 상태 재조회를 진행한다.
- 문의 자동화 판정은 `자동전송`, `승인필요`, `근거부족`으로 나뉜다. 정확히 승인된 규칙과 최신 근거가 모두 맞을 때만 자동전송하며, 일반 AI 초안과 수동 전용 위험 답변은 승인 대기로 남긴다.
- B7에서 최근 1개월, `발송완료`, 반품 클레임을 기준으로 후보를 대조
- 반품 사유가 정확히 `단순변심`이고, 주문 전체 행의 발송완료 상태, 국내 CJ대한통운 코드 `018`, 동일한 원송장이 확인된 건만 검토 후보 생성
- 중복 클레임, 같은 주문의 복수 반품, 기존 반품송장, 원송장 누락·불일치, 미발송 상태는 자동 차단
- 회수 가치 판단은 자동 추정하지 않고 `PICKUP_WORTHWHILE` 또는 `SKIP_NO_VALUE`로 사용자가 명시
- 회수 가치가 있는 주문만 원송장번호로 CJ LOIS 반품예약 후보 생성
- CJ 실제 제출 화면은 전용 Chrome에서 `예약 > 기업고객건별접수`, 반품 예약, 원운송장 조회, `저장하시겠습니까?` 최종 확인까지 학습 완료
- CJ 홈에 로그인된 상태면 `예약 > 기업고객건별접수` 메뉴를 정확히 찾아 자동 이동하며, Chrome 저장 자격증명과 로그인된 네이버 메일 세션으로 로그인 및 이메일 인증을 복구한다. CAPTCHA는 자동 처리하지 않는다.
- 당일 성공 신호는 저장 확인창 종료, 원송장 입력칸 초기화, 접수 목록 행 추가의 세 가지로 판정
- 정확한 기존 접수 안내가 확인되면 중복 예약을 만들지 않고 `DUPLICATE_RESERVATION_DIALOG_VERIFIED` 증거로 감사 기록을 남긴다.
- 2026-10-04 감독 실행에서는 승인된 1회 예외 후보의 기존 CJ 반품예약을 확인하고, 중단 후 재개 경로로 샵플링 B7 `반품접수(R01)` 재조회까지 완료했다. 교환 건은 별도 학습 대기 상태다.
- 반품운송장번호는 접수 직후 비어 있는 것이 정상이다. `npm run local-agent:return-invoice-readback -- --execute`가 접수 감사 기록의 다음 평일 이후에 원송장과 정확히 일치하는 CJ 행을 조회한다.
- CJ 반품운송장번호가 비어 있으면 샵플링을 수정하지 않고 다음 실행에서 재시도한다. 이 방식으로 주말과 택배사 휴무일도 번호 생성까지 자연스럽게 대기한다.
- 번호가 확인되면 정확한 샵플링 주문의 C/S 팝업에서 유형 `메모(R)`에 원송장과 반품송장을 기록하고 재조회로 저장을 검증한다. C/S 완료 체크는 건드리지 않는다.
- 완료 감사 기록에서 주문번호 단위 `CURRENT_CLAIM_AND_PICKUP_STATUS` 근거를 생성하여 반품 수거·반송장 문의 초안에 사용할 수 있다.
- Codex 자동화 `샵플링 반품송장 후속 확인`은 평일 12시 45분에 위 명령을 실행한다. 미생성·미도래·이미 완료 상태는 알림 없이 종료하고, 기록 완료·실패·로그인 개입 필요 때만 보고한다.
- 교환은 수거 시점, 재발송 상품·수량·주소 확인, 송장 출력 순서를 별도로 학습한 뒤 활성화
- 비밀번호는 대화나 로그에 저장하지 않고 전용 Chrome 프로필 또는 OS 보안 저장소 사용

### 6. 평일 예약 실행

상태: 전체 흐름 안정화 후 활성화.

- 택배사 휴무일은 사용자가 일시중지 가능
- 로그인 만료, 매핑 예외, 건수 불일치, 프린터 오류 발생 시 중단하고 알림
- 신규 매핑 예외는 사용자에게 확인받아 규칙으로 축적

### 송장 직접 출력 구현 상태

상태: PDF 생성기와 Windows 직접 출력기 구현 완료. 2026-10-01 실제 운영 배치에서 `Xprinter XP-DT108B LABEL`, `대한통운 송장` 109×127mm, 203dpi, PDF 페이지 수, 드라이버 물리 크기 및 양수 스풀 작업 ID를 검증했고 사용자가 종이 출력의 크기와 순서를 확인했다. 일일 통합 흐름에서는 샵플링 송장 설정창 주문 수와 HTML의 실제 페이지 수를 자동 대조한다.

## 실행 안전 원칙

- 조회와 외부 변경을 분리한다.
- 주문 건수, 송장 장수, 합포장 수를 단계마다 대조한다.
- OCR만으로 주문을 변경하지 않고 Shopling 목록의 운송장번호와 정확히 일치시킨다.
- 신규 예외, 복수 후보, 불명확한 B코드는 자동 처리하지 않는다.
- 실제 삭제, 품절, 송장전송, 인쇄는 각 단계가 검증된 뒤 명시적으로 활성화한다.
- 로그인 비밀번호, 쿠키, 세션, 수취인 개인정보를 로그나 결과 파일에 남기지 않는다.
