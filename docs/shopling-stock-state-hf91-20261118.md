# Shopling 재고상태 HF91 — B코드 엄격 직렬 전송

## 실제 증상

- HF90 확장 v0.6.53은 B코드 1건 실행에서 Shopling 전송과 Commerce OS `전송 접수 완료 1/1건`을 실화면으로 확인했다.
- B코드 2건을 함께 입력하면 Shopling 전송 화면은 일부 진행됐지만 Commerce OS는 `성공 0/2건`으로 끝났다.
- 실패한 두 B코드는 같은 모델번호 `AAA115`의 옵션상품이었다.

## 원인

Commerce OS의 실행 계획은 한 번에 B코드 1건만 배정했지만, 실행 직전에 과거 HF87의 `동일 모델 B코드 합치기`가 다시 적용됐다. 그 결과 같은 모델의 여러 B코드가 하나의 확장 START와 하나의 A21 전송으로 합쳐졌다. 화면 문구의 `1건씩 순차 전송`과 실제 전송 경계가 달랐다.

## 변경

- 통합 입력과 운영 큐 모두 확장 START 한 번에 B코드 정확히 1건만 전달한다.
- 같은 모델번호·같은 목표상태여도 서로 합치지 않는다.
- 한 건의 터미널 접수 결과를 원장에 저장하고 현재 배치를 해제한 다음에만 다음 B코드를 예약한다.
- 다음 B코드는 확장 프로그램이 명시적으로 idle 상태를 응답한 뒤 시작한다.
- 이미 성공한 건은 기존 정책대로 2·3차 시도에서 제외한다.
- 확장 프로그램은 실화면에서 1건 성공이 검증된 HF90 v0.6.53을 그대로 사용한다. 이번 변경은 Commerce OS의 다건 조율 계층 변경이므로 새 확장 설치가 필요 없다.

## 검증 기준

1. 같은 모델 옵션 B코드 2건을 넣어도 첫 START payload에는 첫 B코드만 포함된다.
2. 첫 결과가 끝나기 전에 두 번째 START가 발생하지 않는다.
3. 첫 성공 건은 큐에서 제거되고 두 번째 건만 다음 START로 전달된다.
4. 각 시작 전에 확장 idle 확인이 먼저 수행된다.
5. 최종 화면이 `Shopling 전송 접수 완료 2/2건`이어야 실운영 다건 성공으로 판정한다.
