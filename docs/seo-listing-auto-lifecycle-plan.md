# SEO 상품 자동등록·물갈이 — Shadow v1

## 목표

`/seo-bulk-cloud`를 사람이 등록 대상을 매번 체크하는 업로드 화면에서, 운영자는 월간 성과와 예외만 확인하는 상품 포트폴리오 자동화 화면으로 발전시킨다.

기존 기능은 유지한다.

- 샵플링 일괄 대량등록 및 마켓전송
- 등록 실패 확인과 오류 체크포인트 재실행
- SEO RUN 생성·보관·복구

## 확정 정책

- 정상 판매중 readback이 확인된 시점부터 60일을 한 번의 노출 기회로 계산한다.
- 노출 중 1건이라도 판매되면 `PROTECTED`로 유지한다.
- 60일 동안 판매가 0이면 Shopling 품절 및 삭제전송을 계획하고, 삭제 readback 완료 후 90일 휴지한다.
- 휴지 종료 후 새 SEO RUN을 준비해 재등록한다.
- 최대 3회의 검증된 노출 기회를 준다.
- 3회 모두 무판매인 상품만 `RETIRE_CANDIDATE`로 올린다. 상품 마스터 원본은 삭제하지 않는다.
- 기술 오류, 마켓 미노출, 판매중 readback 부재는 기회를 소비하지 않고 예외로 보낸다.
- 상품별 계절성은 추정하지 않는다. 60일 노출 + 90일 휴지가 여러 시기를 통과하게 하는 단순 정책으로 대체한다.

## Shadow v1 안전 경계

이 단계는 판단과 화면만 제공하며 Shopling 또는 마켓에 쓰지 않는다.

- 자동 실행은 코드에서 `false`로 고정한다.
- 데이터베이스 정책 기본값도 `enabled=false`, `mode=shadow`다.
- 실행 스케줄/dispatcher를 등록하지 않는다.
- 마켓별 최대 등록수·현재 등록수·진행중 수량·안전 여유를 모두 확인한다.
- 필수 마켓 한 곳이라도 값이 없거나 오류이거나 24시간보다 오래되면 전체 자동 배치를 차단한다.
- 여러 마켓에 함께 보내므로 남은 슬롯을 더하지 않고 가장 작은 필수 마켓 슬롯을 배치 상한으로 사용한다.
- 한 상품의 여러 SEO RUN 중 최신 RUN 하나만 자동선택 후보가 될 수 있다.
- 불확실한 외부 쓰기는 재시도하지 않으며 향후 `confirm_needed`로 분리한다.

### 마켓 한도 readback 계약

- 현재 상품그룹 레지스트리의 29개 마켓 계정만 수집 대상으로 허용한다.
- 수집기가 일부 계정을 확인하지 못해도 서버가 29개 전체 스냅샷을 만들고, 누락 계정은 `unknown`으로 저장한다. 따라서 누락을 0건으로 오해하지 않는다.
- 스냅샷은 owner와 UUID로 식별하며, 24시간을 지난 증거와 5분보다 미래인 증거는 받지 않는다.
- 29개 행을 한 RPC에서 원자적으로 반영하고, 더 오래된 스냅샷은 최신 값을 덮지 못한다.
- 저장 타임아웃은 성공·실패가 불명확한 쓰기다. 같은 스냅샷 29개를 한 번 재조회해 전부 일치할 때만 성공으로 대사하며, 불일치하면 `confirm_needed`로 끝내고 쓰기를 자동 재시도하지 않는다.
- 이 POST는 Commerce OS 내부 증거 저장만 수행한다. Shopling 또는 마켓에는 쓰지 않는다.

## 데이터 소유권

- 상품의 기준 진실: 기존 Product Master / product launch item
- SEO 등록 준비: 기존 `seo_run_jobs`
- Shopling/마켓 식별자: listing lifecycle ledger의 `goods_key`, `market_listing_id`
- 물갈이 ledger는 상품 원본을 복제하거나 삭제하지 않는다.

## 상태 흐름

`READY → LIVE → PROTECTED`

또는

`READY → LIVE → COOLDOWN → READY → LIVE → COOLDOWN → READY → LIVE → RETIRE_CANDIDATE`

외부 증거가 부족하거나 기술 실패가 발생하면 `EXCEPTION`으로 보낸다.

## Shadow v1 인수 조건

1. `/seo-bulk-cloud` 상단에 자동등록·물갈이 현황이 보인다.
2. 기존 일괄등록·마켓전송·오류 재실행 컨트롤이 그대로 존재한다.
3. 59일에는 유지하고 정확히 60일에 무판매 물갈이를 계획한다.
4. 휴지 종료 직전에는 재등록하지 않고 정확한 종료 시점부터 재등록 후보가 된다.
5. 3번째 무판매 노출 뒤에는 재등록이 아니라 단종 후보가 된다.
6. 판매 1건 이상이면 보호한다.
7. 기술 오류와 미검증 노출은 횟수를 늘리지 않는다.
8. 마켓 한도 readback이 없거나 24시간보다 오래되면 자동등록 예상 수량은 0이다.
9. 필수 마켓 슬롯 20개와 5개를 합쳐 25개로 보지 않고 5개만 안전 배치한다.
10. 현황 API는 owner 범위 GET만 제공한다. 별도 한도 readback POST는 인증된 owner의 29개 증거만 원자 저장·재조회하며 외부 마켓에는 쓰지 않는다.

## 다음 단계와 실제 운영 전 증거

Shadow v1 이후 아래 순서로만 확장한다.

1. Shopling/마켓별 최대 등록수와 현재 등록수를 읽는 로컬 collector 연결(서버 수집 계약과 저장 경로는 구현됨)
2. 상품별 실제 판매중 시작일, 판매량, 품절·삭제 완료 readback 연결
3. Shadow 예상과 사람이 확인한 결과의 대사
4. 소수 상품·소수 계정 Canary 등록
5. 등록/품절/삭제 각각의 식별자 readback 및 중복 방지 검증
6. 월간 요약과 예외함 운영 검증
7. 별도 소유자 승인 후에만 Auto 전환

Production migration 적용과 실제 마켓 쓰기 활성화는 이 문서 작성만으로 승인된 것이 아니다.
