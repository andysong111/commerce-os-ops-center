# 발주차시 온디맨드 재구축 작업기록 — 2026-10-25

## 목표

운영자가 `이번 발주차시 시작` 한 번으로 예산을 입력하고, 최신 판매·클레임·재고·진행 중 주문을 자동 준비한 뒤 사용자용 발주초안에서 검토와 1688 장바구니 준비까지 끝내도록 한다.

## 확정 흐름

1. 총 사용 현금과 신규상품 소싱예산 비율 입력
2. 최신 근거 자동 준비 및 안전 대조
3. 신규상품 소싱엔진 선택 또는 직접 추가
4. 기존상품 대략 재고·수량·수동 B코드 고정·5/10단위·제외 보정
5. 한 번 재계산
6. 5-1 실제 위안단가·중국내 운임 기록 후 최종 예산 재계산
7. 5-2 확정수량·옵션을 1688 장바구니에 반영·검증
8. 주문 제출과 결제는 사용자가 직접 수행

## 안전 기준

- 새 판매수집 범위의 시작은 직전 발주차시 계산 시작일이다.
- 월별 예산 적립과 12개월 매출 판정은 유지하고 월간 자동 준비 스케줄은 폐기한다.
- 동일 날짜의 열린 차시가 있으면 새 차시를 중복 생성하지 않고 기존 초안을 연다.
- 자동화는 주문 제출·결제를 호출하지 않는다.
- 5-2는 실제 원가·옵션·최종 예산 검증이 끝나기 전에는 열리지 않는다.
- 배송대행지 바코드 전달은 선택한 발주초안 ID로 품목을 제한해 같은 달의 다른 차시 주문과 섞지 않는다.

- 이전 차시 계산일 경계와 같은 날짜 중복 시작 방지
- 월간 준비 스케줄 퇴역과 디스패처 회귀

## 2026-10-25 운영 시간초과 보강

- 운영 로그에서 발주차시 시작 API가 Product Master 기준정보 15초 제한에 걸린 뒤 동일 요청을 약 1초 간격으로 반복하는 현상을 확인했다.
- Product Master 기준정보는 계산 결과가 같은 집계형 원장 RPC로 바꿨다. 최초 읽기는 70초 한 번으로 제한하고, 최근 72시간 내 지문·상품수까지 일치하는 저장 스냅샷만 대체 근거로 허용한다.
- 판매자료 준비도 같은 검증된 기준정보 읽기 경로를 사용해 별도의 짧은 제한에서 다시 실패하지 않게 했다.
- 한 API 요청은 주문·클레임 또는 판매자료 한 단계만 처리한다. 같은 단계·진행률·오류가 2회 연속이면 브라우저 자동 반복을 중단하고, 사용자가 같은 버튼으로 저장된 단계부터 재개할 수 있게 한다.
- 시간초과가 발생한 실제 준비 단계가 화면과 서버 로그에 남으며, 주문 제출·결제는 여전히 실행하지 않는다.
- 시작 팝업을 다시 열 때 이전 실패 문구와 진행률을 초기화해 새 시도가 과거 실패처럼 보이지 않게 했다.
