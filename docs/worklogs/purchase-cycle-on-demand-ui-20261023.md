# 주문 가능 시점 발주 전환 · 작업 기록

## 목표

- 발주초안 각 행에서 B코드, 모델명, 모델번호, 판매 옵션을 함께 보고 대략 재고를 `많음 / 보통 / 적음 / 품절` 버튼으로 선택한다.
- `재고상태 저장 후 발주안 재계산` 한 번으로 선택값을 저장하고 같은 발주차시의 Draft를 교체한다.
- 새 발주차시는 달력월 1회가 아니라 가장 최근 `입고확정일 <= 판매·수량 근거 < 이번 발주 시작일` 구간으로 계산한다. 입고일 기록이 없는 과거 자료만 이전 발주시작일을 보조 기준으로 쓴다.
- 발주 가능액은 기존처럼 완료된 달의 정상매출 50%를 월별로 적립한다. 쓰지 않은 금액은 이월하고, 실제 주문완료 금액만 누적 잔액에서 차감한다.
- 같은 달에 여러 번 발주할 수 있으며 각 발주차시는 같은 누적 잔액을 이어서 사용한다. Draft 생성·미리보기는 잔액을 차감하지 않는다.
- 월별 매출 4만원 충족 횟수와 12개월 평균매출 등 상품 우선순위 규칙은 그대로 유지한다.
- 메인 관리는 월 탭 대신 발주차시 목록을 쓰고, 완료 차시는 입고확정일별 이력으로 보존한다. 월별 예산 원장은 내부 계산 근거로 유지한다.

## 안전 경계

- 재고 버튼은 발주 계산용 `OPERATOR_ESTIMATE`만 저장하며 정확 재고나 Shopling 판매상태를 바꾸지 않는다.
- 기존 정확 재고와 이후 입고 기록이 대략 재고보다 우선한다.
- 저장 또는 재계산이 실패하면 기존 Draft를 주문 가능한 새 Draft로 가장하지 않는다.
- 1688 장바구니, 주문, 결제, 공급자 연락은 실행하지 않는다.

## 완료 기준

1. Draft 행에서 모델명·모델번호·옵션과 재고 4단계 버튼이 보이고 키보드로도 선택할 수 있다.
2. 변경이 없으면 재계산 버튼이 비활성화되고, 선택이 있으면 활성화된다.
3. 잘못된 B코드·재고단계·Draft 밖 B코드는 서버에서 차단한다.
4. 재고 저장 후 최신 재고를 다시 읽어 Draft를 재계산하고 새 Draft 주소로 이동한다.
5. 같은 Draft 재계산은 최초 발주 시작일을 유지한다.
6. 다음 새 발주차시는 가장 최근 입고확정일을 이전 기준일로 삼고 같은 달에도 만들 수 있다.
7. 기존 월간 기록은 계속 읽을 수 있고 실제 주문·결제는 일어나지 않는다.
8. 예산은 완료된 월별 정상매출에서 누적되고, 같은 달 주문완료 2건도 각각 한 번씩 차감되며 Draft는 차감되지 않는다.
9. 단위·API·UI 회귀 테스트, 타입검사, 린트, 빌드, 배포 후 브라우저 확인이 통과한다.
