# 모바일 피킹 재고 반영

피킹 후 선반에 남은 수량을 실사 기준재고로 저장한다. 재고없음을 명시한 항목에만 품절 직접 전송을 요청한다. 기존 체크 전용 카톡 링크는 유지하고, 재고 확정은 소유자 세션으로 제한한다.

검증 순서는 목록·B코드 검증, 재고 원장과 완료 기록의 원자적 저장, PC 확장의 직렬 접수, 결과 재조회다. 운영 데이터 변경 없이 격리된 데이터로 확인한다.

## 실행 조건과 판정

- 휴대폰의 완료 요청은 모바일 업무센터 소유자 로그인, 같은 출처, 당일 최신 피킹 목록, B코드와 기존 모델번호가 확인되어야 한다. 품절의 직접 전송은 기존 Ops Center 한도인 50개 B코드까지다.
- 수량 0만 입력하면 피킹 실사 0개로 기록한다. 품절 전송은 ‘재고없음’을 명시한 항목에만 생성한다. 바구니에 담은 수량은 입력한 실사 수량에서 다시 빼지 않는다.
- 품절·실사 원장, 피킹 완료, 전송 대기 기록을 한 DB 트랜잭션에서 확정한다. Windows 모바일 업무센터 수신기는 영업 작업 허용 설정에서 기존 재고·품절 페이지를 열고, 로그인한 운영자와 지원되는 Chrome 확장이 현재 운영 큐를 확인한 뒤 B코드별로 전송한다.
- 실제 전송 시작 기록이 생긴 작업은 자동 재발행하지 않는다. 휴대폰의 ‘접수 완료’는 해당 B코드의 원래 샵플링 전송계획 전체 접수 기록이 있을 때 표시한다. 결과 불명·실패는 운영 큐에서 원래 접수 기록을 확인한다.
- 적용 순서는 DB 마이그레이션, 웹 배포, Windows 모바일 업무센터 수신기 업데이트다. 로컬 업무센터의 운영 정보로 테스트하지 않았다.

## 검증 기록

휴대폰 390×844 Chrome에서 품절 표시, 체크, 실사 수량, 새로고침 복구, 변경분 탭, 완료와 결과 조회를 확인했다. PC의 실제 품절 페이지와 모의 확장을 연결해 BAD5-2 접수 뒤 BAF5-1이 시작되는 순서를 확인했다. PostgreSQL 호환 격리 DB에서 운영 역할 권한, 잘못된 목록과 버전, 중간 실패 롤백, 재시도·충돌, 중복 수신 차단과 시작기록 전 복구를 검증했다. 재현 테스트는 CI의 피킹 단위검사 및 PostgreSQL 트랜잭션 작업에 포함한다.

관련 Node 테스트 66건, 변경 경로 ESLint, 고정된 의존성을 새로 설치한 복사본의 기본 프로덕션 빌드(정적 페이지 134개)가 통과했다. 운영 Windows 자동화 Chrome 프로필에 재고상태 확장 HF102(0.6.62)가 사용 설정된 것도 읽기 전용으로 확인했다. 실제 운영 DB 적용, 소스 공개, PC 수신기 교체 및 실제 상품 전송은 별도 운영 승인 대상이다.
