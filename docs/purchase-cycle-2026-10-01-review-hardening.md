# 10월 발주 사전점검 · 추가 검증 / PR 1210 후속

## 수정한 코드 검토 사항

1. 금액은 planning의 expectedCost/판매가 50% 추정값이 아니라 실제 확정 입고원가와 보호원가 중 큰 단가 × 기존 엔진 추천수량으로 계산한다. 양수/안전한 정수 연산을 검증하고 이 금액으로 정렬·현금 상한·출력을 통일한다. 수량을 임의로 축소하지 않는다.
2. 새 wrapper 생성시각으로 재고 신선도를 인정하지 않는다. Product Master inventory/cost 응답의 generatedAt와 contentFingerprint를 전달하고 15분 기준 및 지문을 필수로 확인한다. 누락·오래됨·미래시각은 7~8구간도 차단한다.
3. 목표 발주월의 기존 결제기록을 원래 읽기 전용 요약기에서 조회 전후 두 번 확인한다. 지출액/원본이 바뀌거나 조회 실패하면 0원으로 간주하지 않는다. 전월 매출 기반 전체예산에서 이미 기록된 지출을 차감한 뒤 사용자 현금 상한을 적용하고, 기존 배송비 여유 배수로 상품대금 한도를 나눈다. 상품대금·전체 현금 한도·배송비 여유분 포함 예상액은 화면에서 구분한다.
