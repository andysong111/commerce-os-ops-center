# 온돌패스 입고현황 확인 인수인계 (2026-11-21)

## 운영 목표

업무센터의 `11-2. 온돌패스 입고현황 확인`이 확정된 바코드 작업의 신청번호만 읽고, 온돌패스 LCL 신청현황의 품목별 입고수량을 Ops Center 4단계 입력 제안으로 준비한다. 외부 화면 관찰과 재고 입고확정을 분리해, 실제 재고·Product Master·Shopling 변경은 운영자가 `입고확정`을 누를 때만 실행한다.

## 확정 계약

- 대상 Draft: `fast-purchase-draft:5cabcbeeffd1b884a074`
- 바코드 종결 근거: 신청번호 8건, 원본 102행, B-code 101개, 주문수량 9,672개
- 정확 식별자: `신청번호 + 행번호`
- 입고 근거: 수량 셀의 별도 빨간 `입고` 표식
- 차단 조건: 행 누락·중복, 주문번호 매칭 실패, 알 수 없는 상태, 종결 근거 해시 변경, 이미 입고된 행의 상태 회귀
- `폐기` 행과 불일치 행은 제안수량에서 제외하며 전량 입고로 판정하지 않는다.

## 구현 범위

- 서버는 바코드 완료 근거에 신청번호·행번호·주문번호를 동결하고, 온돌패스 관찰 스냅샷을 append-only 운영기록으로 저장한다.
- 같은 실행의 정확한 재전송(같은 확인시각)만 중복 저장하지 않는다. 확인시각이 다른 즉시·예약 실행은 화면 수량이 같아도 새 운영기록으로 저장해 Ops Center의 최신 적용시각을 갱신한다.
- B-code별 제안수량은 `검증된 누적 입고수량 - 이미 확정된 입고원장 수량`으로 계산한다. 남은 주문수량보다 적거나 많아도 실제 입고수량을 자르지 않는다.
- Ops Center 4단계는 최신 관찰시각·정상/부족/초과/대기/폐기/주문 매칭 실패 현황을 표시한다. 수동 입력도 부족·초과를 허용하며 `전체 정상입고 처리`는 모든 품목의 남은 주문수량을 한 번에 확정한다.
- 11-2 즉시·예약 실행 결과는 별도 적용 버튼 없이 Ops Center 4단계 제안수량으로 사용한다. 화면을 나중에 열면 최신값으로 시작하고, 이미 열려 있으면 포커스 복귀 시 즉시 또는 최대 15초 안에 새 결과를 감지해 갱신한다.
- 업무센터는 즉시 실행과 1~24시간 간격·최대 1~48회 예약을 제공한다. 전량 입고가 검증되면 자동 종료하고, 업무센터 탭이 닫히면 실행하지 않는다.
- Chrome 확장 v0.3.48은 로그인된 LCL 신청현황 탭 하나만 읽는다. 신청번호 집합이 다르거나 탭이 없거나 둘 이상이면 실행하지 않는다.

## 실제 화면 근거

2026-11-21 로그인된 온돌패스 화면에서 102행 중 `입고` 감지 52행, 미입고 대기 49행, `폐기` 1행을 읽기 전용으로 확인했다. 입고 감지 52행은 정상입고 51행과 초과입고 1행으로 구성되며, 부족입고 0행·주문 매칭 실패 0행이다. 화면 표시수량 합계는 9,677개이고 바코드 종결 근거는 9,672개여서 5개 차이가 있다. 전 행 주문 매칭은 정상이며 `BCE6-3` 한 행이 주문 10개·입고 15개다. 수량 차이는 차단 사유가 아니라 `부족 입고` 또는 `주문보다 많이 입고`로 분류해 실제 입고수량을 제안한다.

## 운영 절차

1. Chrome 확장 v0.3.48을 한 번 새로고침한다.
2. 일반 Chrome에서 온돌패스 로그인과 LCL 신청현황 탭을 하나만 유지한다.
3. 업무센터에서 대상 발주초안을 선택하고 `11-2. 온돌패스 입고현황 확인`을 누른다.
4. Ops Center 4단계에서 부족·초과·주문 매칭 실패·폐기 행과 B-code별 제안수량을 확인한다.
5. 실제 도착수량이 맞을 때만 운영자가 `입고확정`을 누른다.
