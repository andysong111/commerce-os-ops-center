# Shopling 재고상태 HF41 운영 인계 (2026-10-30)

## 실제 장애 근거

- HF40 v0.6.8에서 카나리 `BBB4-3` 한 건만 실행했다.
- Shopling 결과 화면은 약 125초 뒤 정확한 완료 문구 `상품상태 변경 전송이 완료되었습니다.`를 표시했다.
- 개별 마켓 실패(토스의 존재하지 않는 상품, GS Shop의 쇼핑몰상품코드 없음)는 기존 정책대로 전체 전송 완료와 별개인 안내 결과였다.
- 기존 결과 감시기는 95초에 종료되어 완료 문구가 나타나기 전에 이탈했다. 따라서 Commerce OS는 `BBB4-3`을 계속 처리 중으로 남겼다.
- 결과 화면은 완료 상태로 열려 있으므로 같은 상품을 다시 전송하면 안 된다. 나머지 14건은 실행하지 않았다.

## HF41 변경

- 버전: v0.6.9 HF41
- 단건 결과 감시 시간을 95초에서 30분으로 늘렸다.
- 확장 서비스 워커가 다시 시작되면 기존 완료 결과 탭을 찾아 복구한다.
- 복구 경로는 기존 결과를 판독할 뿐 새 Shopling 전송을 호출하지 않는다.
- 정확한 완료 문구와 안정화 확인, Commerce OS ACK 이후 결과 탭 종료 계약을 유지한다.
- 이 실장애의 125초 지연을 재현하는 영구 회귀 테스트를 CI에 추가했다.

## 운영 순서

1. HF41 v0.6.9만 활성화하고 Commerce OS에서 연결 버전을 확인한다.
2. `BBB4-3`을 다시 클릭하지 않는다. 서비스 워커 부팅 복구로 기존 완료 결과가 확정되는지 확인한다.
3. `BBB4-3`이 성공 처리되어 대기열에서 빠진 경우에만 나머지 14건을 순차 처리한다.
4. `BCC5-1`, `BCC5-2`만 `판매중`, 나머지는 `품절`이다.
5. `BCC6-2`는 예외 건으로 처리하지 않는다.
6. 실패 또는 확인 불가가 발생하면 같은 B코드를 자동 재시도하지 않고 즉시 중단한다.

## 검증 기록

- HF41 및 재고상태 관련 회귀 테스트 139건 통과.
- TypeScript 타입 검사와 대상 ESLint 통과.
- 운영 빌드 통과.
- 생성 ZIP의 manifest 버전 v0.6.9, 서비스 워커 `background-v073.js`, 30분 감시 패치와 부팅 복구 코드를 확인했다.
- 로컬 verify 응답은 `singleResultWatchMs=1800000`, `liveObservedResultDurationMs=125000`, `resendRequiredForRecovery=false`를 반환했다.
