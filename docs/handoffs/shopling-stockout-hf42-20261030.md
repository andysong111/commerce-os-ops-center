# Shopling 재고상태 HF42 운영 인계 (2026-10-30)

## 실제 장애 근거

- HF41 v0.6.9에서 카나리 `BCB6-2` 한 건만 실행했다.
- Shopling 결과 화면은 정확한 완료 문구 `상품옵션 수정 전송이 완료되었습니다.`를 표시했다.
- 같은 화면에 과거 진행 제목 `상품옵션 수정 전송중입니다.`가 마켓별 결과 영역에 남아 있었다.
- 기존 감시기는 화면 어디든 `처리중입니다`가 있으면 완료 문구보다 우선해 계속 대기했다. 따라서 Commerce OS는 `BCB6-2`를 처리 중으로 남겼다.
- 일부 마켓 실패는 기존 정책대로 Shopling 상태 전송 완료와 별개의 안내 결과다.
- 완료 결과 탭과 확장 저장 상태가 남아 있으므로 `BCB6-2`를 다시 전송하면 안 된다.

## HF42 변경

- 버전: v0.6.10 HF42
- 정확한 옵션 완료 문구가 있으면 과거 진행 제목보다 우선해 최종 완료로 판정한다.
- 옵션 결과 감시 시간을 30분으로 유지한다.
- 확장 서비스 워커가 다시 시작되면 저장된 활성 작업과 기존 결과 탭을 찾아 복구한다.
- 복구 경로는 기존 결과를 판독할 뿐 새 Shopling 전송을 호출하지 않는다.
- Commerce OS 성공 ACK가 끝난 뒤에만 관리 중인 결과 탭을 닫는다.
- 실제 장애 조합인 `과거 진행 제목 + 정확한 완료 문구`를 영구 회귀 테스트에 추가했다.

## 운영 순서

1. 현재 로드된 HF41 확장 폴더의 파일만 HF42 v0.6.10으로 교체해 같은 확장 ID와 저장 상태를 유지한다.
2. 기존 확장 카드에서 새 확장을 추가하지 말고 `새로고침`만 누른다.
3. `BCB6-2`를 다시 클릭하지 않는다. 서비스 워커 부팅 복구로 기존 완료 결과가 성공 처리되는지 확인한다.
4. `BCB6-2`가 대기열에서 빠지고 결과 탭이 닫힌 경우에만 다음 건을 진행한다.
5. `BCC5-1`, `BCC5-2`만 `판매중`, 나머지 미처리 건은 `품절`이다.
6. `BBB4-3`은 Shopling에서 이미 완료됐지만 Commerce OS 기록이 없으므로 다시 전송하지 않는다.
7. `BCC6-2`는 예외 건으로 처리하지 않는다.
8. 실패 또는 확인 불가가 발생하면 같은 B코드를 자동 재시도하지 않고 즉시 중단한다.

## 검증 기록

- HF42 핵심 회귀 테스트 18건 통과.
- Shopling HF와 재고상태 관련 회귀 테스트 150건 통과.
- TypeScript 타입 검사와 대상 ESLint 통과.
- 실제 Windows 권한 운영 빌드 통과. 샌드박스 빌드의 Turbopack 하위 프로세스 실패는 환경 제한으로 확인했다.
- 전체 재고 테스트 묶음에서 HF42와 무관한 기존 기대값 불일치 1건(`InventoryStockOperationalDetails`의 큐 read fresh 인자)만 별도로 확인했다.
