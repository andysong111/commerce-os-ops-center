# Shopling 활성 작업 후속 등록 연결 — 2026-11-17

## 문제

- Shopling 상품 DB는 `6,087 / 10,000`으로 신규 등록 여유가 있었다.
- 그러나 이전 원클릭 마켓전송 작업이 살아 있으면 UI가 그 작업만 재연결한 뒤 종료했다.
- 같은 실행에서 새로 선정된 상품은 기존 작업에 포함되지 않았는데도 후속 등록 목록이 사라져 신규 등록이 `0건`으로 남을 수 있었다.

## 변경

- 활성 작업과 오늘 요청 RUN을 비교해 기존 작업에 없는 RUN만 `continuationRunIds`로 보관한다.
- 활성 작업의 서버 상태가 종료되기 전에는 후속 작업을 만들지 않는다.
- 정상 종료 또는 확인필요 종료 확인 후 보관된 RUN만 새 원클릭 작업으로 생성해 Shopling 등록과 마켓전송을 이어간다.
- 새 작업 생성 전 토큰과 RUN 목록을 브라우저 저장소에 먼저 기록해 새로고침·일시적 409 경합에도 같은 요청으로 복구한다.
- 15초 복구 루프에는 단일 실행 잠금을 두어 후속 작업이 중복 생성되지 않게 한다.

## 안전 계약

- 활성 에이전트의 lease는 빼앗지 않는다.
- 기존 작업에 포함된 RUN은 다시 Shopling 등록하지 않는다.
- 기존 작업이 예외·취소로 끝나면 후속 신규 등록은 실패 닫힘으로 중단한다.
- 서버가 동일 상품의 활성 작업 409를 반환하면 후속 목록을 삭제하지 않고 다음 확인 때 재시도한다. 다른 검증 409는 자동 반복하지 않는다.
- 브라우저가 닫혀 있는 동안 외부 등록을 새로 시작하지 않는다. Commerce OS 페이지와 v0.3.47 Sender가 다시 연결되면 저장된 후속 목록을 이어간다.

## 검증 기준

- 부분 겹침: 기존 RUN 제외, 신규 RUN만 후속 등록.
- 완전 겹침: 후속 등록 0건, 기존 작업만 재연결.
- 중복 RUN 입력: 후속 목록에서 1회로 정규화.
- 활성 작업 미종료: 새 원클릭 작업 생성 금지.
- 활성 작업 종료: 후속 작업 1회 생성 및 기존 Shopling → 마켓전송 흐름 사용.
- 테스트 중 실제 Shopling/마켓 외부 쓰기 실행 금지.
