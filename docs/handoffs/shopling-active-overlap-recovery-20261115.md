# Shopling 원클릭 활성 작업 중복 재연결 — 2026-11-15

## 운영 증상

- 사용자가 `오늘 자동운영 1번 실행`을 한 번 눌렀다.
- Commerce OS는 `같은 상품의 마켓전송 작업이 이미 진행 중입니다. 작업번호 3e2ada48`을 표시했다.
- Shopling A4의 2026-11-15 등록 조회는 0건이었다.
- Commerce OS 화면은 같은 작업에 대해 `브라우저 에이전트 연결 복구 완료`와 `최근 원클릭 · 마켓전송 준비`를 표시했다.

## 원인과 안전 판단

- `3e2ada48`은 삭제할 유령 작업이 아니라 비종료 상태로 남아 브라우저 에이전트가 재연결한 기존 원클릭 작업이다.
- 새 버튼 흐름이 기존 작업과 겹치는 RUN을 다시 생성하려 해 서버 중복 방어가 409로 차단했다.
- Shopling 등록 0건은 중복 전송이 발생하지 않았다는 근거다. 기존 작업 삭제·취소나 Shopling 재등록은 수행하지 않았다.

## 변경

- 새 원클릭 작업을 만들기 전에 비종료 오케스트레이션과 RUN 겹침을 확인한다.
- 겹침이 있으면 새 작업을 만들지 않고 기존 작업의 안전한 `reconnect` 경로로 토큰을 재발급하고 브라우저 에이전트에 다시 인계한다.
- 조회와 생성 사이 경합으로 서버가 409를 반환해도 목록을 다시 읽어 동일한 재연결 경로로 복구한다.
- 실패한 새 생성 시도의 로컬 인계 정보는 제거해 15초 자동 복구가 같은 409를 반복하지 않게 한다.
- 시장 전송 중 활성 lease는 기존 reconnect 정책대로 빼앗지 않는다.

## 회귀 고정과 검증

- `tests/shoplingMarketAutoResumePolicy.test.mjs`에 실제 오류번호 `3e2ada48` 회귀 픽스처를 추가했다.
- 활성 겹침은 재연결 대상으로 찾고, 종료 작업과 비겹침 작업은 제외함을 검증한다.
- UI가 생성 전 검사와 409 경합 복구를 모두 사용함을 검사한다.
- 통과: 정책/재연결/자동운영 계약 테스트 22개, TypeScript, 대상 ESLint, `npm run build`.

## 운영 배포 후 확인

- Commerce OS를 새로고침한 뒤 기존 `3e2ada48` 상태가 재연결 또는 진행 중으로 표시되는지 확인한다.
- 버튼을 다시 누를 필요는 없다. 재고 동기화 이후 다음 정상 하루 실행에서 같은 활성 작업이 있으면 새 중복 생성 없이 기존 작업으로 이어져야 한다.
- 실제 마켓 제출 성공 여부는 Shopling/마켓 readback과 원클릭 종료 상태로 별도 확인한다.
