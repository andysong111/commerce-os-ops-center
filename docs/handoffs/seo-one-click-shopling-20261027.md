# 상품출시 SEO → Shopling 원클릭 handoff (2026-10-27)

## 목표

상품출시 진행관리에서 현재 필터의 SEO 등록 가능 상품을 최대 50개까지 한 번에 고르고, SEO FINAL 완성 후 Shopling 6채널 등록큐까지 자동으로 이어간다.

## 안전 규칙

- 품절·단종·입고대기·재료부족·재고확인 불가 상품은 기존 서버 검증에서 제외한다.
- 일부 옵션 품절 상품은 판매 가능한 옵션만 동기화할 수 있을 때만 허용한다.
- 실제 실행 전 상품 수와 작업 범위를 확인창으로 한 번 알린다.
- 자동등록 의도는 RUN별로 저장해 같은 배치의 수동 RUN을 자동등록하지 않는다.
- SEO FINAL이 완성되고 등록 상태가 `idle`인 RUN만 `queued`로 바꾼다.
- 등록 실패·불확실 결과는 자동 재등록하지 않고 기존 실패/재시도 화면에 남긴다.
- Shopling 성공은 기존 6개 goods_key 실재 readback과 후처리 검증을 그대로 사용한다.

## 검증 기록

- 신규 원클릭 회귀검사 및 관련 핵심검사 통과.
- Product Launch Tracker CI 대상 전체 245개 테스트 통과.
- `npm run typecheck`, 변경 TS/TSX ESLint, `npm run build` 통과.
- 실제 상품등록은 검증 중 실행하지 않는다. 운영 배포 후 버튼 표시와 확인창 취소 경로만 브라우저에서 확인한다.

## 운영 장애와 보강 (2026-10-27)

- 현상: 원클릭 버튼에서 약 42개가 선택됐지만 `/api/seo-run-jobs`에 새 RUN이 0개였고 SEO 클라우드 창도 열리지 않았다.
- 최초 실패 경계: 상품출시 화면의 `localStorage/새 창` 전달 단계였다. 서버·DB까지 요청이 도착하지 않았으므로 SEO 생성이나 Shopling 중복등록은 발생하지 않았다.
- 변경: 원클릭은 새 창보다 먼저 `/api/seo-run-jobs`에 직접 POST하고, 서버가 접수한 것을 확인한 뒤에만 진행 화면을 연다.
- 재시도 안전: 브라우저에 같은 상품의 미전송 배치가 남아 있으면 기존 RUN ID를 재사용한다. API는 RUN ID 충돌을 무시하므로 중복 회차를 만들지 않는다.
- 실패 안전: 서버 접수가 실패하면 진행 화면을 열지 않고 미전송 배치를 보존한다. 다른 상품의 미전송 배치가 있으면 합쳐서 실행하지 않고 사용자에게 먼저 확인하도록 막는다.
- 회귀검사: 서버 접수 전 창 열기 금지, 접수 실패 시 복구 배치 보존, 같은 배치 재시도 시 RUN ID 재사용을 실제 handoff 코드로 검증했다.
- 전체 확인: 상품출시 245개, SEO 116개, 타입 검사, 변경 파일 lint, 운영 빌드가 모두 통과했다.
