# Shopling 재고상태 HF39 운영 인계 (2026-10-30)

## 실제 장애 근거

- 카나리 `BBB4-3`는 A6에서 정확한 상품키 12개를 수집한 뒤 A21 묶음 전송 직전에 안전 실패했다.
- 실패 코드는 `SINGLE_A21_BATCH_DISPATCH_FAILED_AFTER_A6`, 내부 코드는 `SINGLE_A21_BATCH_CANONICAL_WORKER_NOT_READY`였다.
- 실제 상품 상태는 변경되지 않았고 A6의 12개 행은 모두 `판매중`으로 남았다.
- 원인은 A4 화면에 전역 메뉴명 `쇼핑몰상품수정`이 존재해 역할 스캐너가 A4를 A21로 오인한 것이었다.

## HF39 변경

- 버전: v0.6.7 HF39
- A4의 정확한 경로·화면 조건을 A21보다 먼저 판별한다.
- A21은 `쇼핑몰상품수정`과 `상품 수정전송`이 모두 존재할 때만 인정한다.
- A21 작업 스크립트 준비를 8초 동안 확인하며 스크립트 주입은 최대 한 번만 수행한다.
- 정확한 A21 준비 전에는 상품 상태를 변경하지 않는다.

## 운영 순서

1. v0.6.7 설치 후 Commerce OS에서 `READY` 연결을 확인한다.
2. `BBB4-3`을 한 번만 재실행해 실제 장애 회귀를 확인한다.
3. 성공 시 대기열을 순차 처리한다. `BCC5-1`, `BCC5-2`만 `판매중`, 나머지는 `품절`이다.
4. 각 건의 Shopling 반영·전송·종료 결과가 `SUCCEEDED`인지 확인한다.
5. 실패 또는 확인 불가가 발생하면 같은 B코드를 자동 재시도하지 않고 즉시 중단한다.
