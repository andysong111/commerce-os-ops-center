# Shopling 품절 HF37 (`v0.6.5`) — 2026-10-29

## 확인된 장애

- `BBB4-3` 단건 품절 작업은 `SEARCH_DATE_FIELDS_AMBIGUOUS`로 종료됐다.
- Commerce OS 화면의 `현재 Lane 없음`, `SINGLE_EXCEPTION`, 예외 큐 기록으로 이 실행은 진행 중이 아니라 실패 종료 상태였다.
- 해당 실패는 A4 검색 시작일·종료일을 지정하는 단계에서 발생했으므로 상품 검색, A6 상태 변경, A21 전송은 시작되지 않았다. `BBB4-3`은 이 실행으로 Shopling에 반영되지 않았다.
- 실제 A4 화면에서 검색 기간 입력칸 두 개가 비어 있었다. HF36의 보조 탐지는 현재 값이 날짜 형식인 입력칸만 후보로 인정해, 비어 있는 정상 날짜 입력칸을 찾지 못했다.

## HF37 변경

- A4에서 날짜 의미가 있는 동일 행의 고유한 빈 입력칸 두 개도 검색 기간 후보로 인정한다.
- 고유한 한 쌍일 때만 `2023-01-01 ~ KST 오늘`을 채운다.
- 날짜 후보가 없거나 여러 쌍이면 아무 값도 쓰지 않고 검색 전에 차단한다. 진단 근거에는 후보와 `mutationAttempted: false`를 남긴다.
- HF36의 정확한 `tabId + frameId` 소유권과 모든 상태 변경·결과 검증 보호 규칙은 유지한다.
- 운영 화면에는 원시 상태코드 대신 `대기 중`, `작업 종료 · 성공`, `작업 종료 · 실패/확인 필요`를 표시한다. 단건 종료 시 Shopling 반영 여부, 자동 재시도 여부, 종료 시각을 별도 결과 상자로 유지한다.
- Commerce OS 최소 확장 버전은 `v0.6.5`로 올리고 이전 버전 실행을 차단한다.

## 검증

- 빈 날짜 입력칸이 정확히 두 개인 정상 A4 화면에서 시작일 `20230101`, 종료일 KST 오늘을 채우는 회귀 테스트가 통과했다.
- 날짜 후보가 세 개인 모호 화면에서는 어떤 입력칸도 변경하지 않고 검색 전 차단하며 진단 근거를 남기는 회귀 테스트가 통과했다.
- HF37 포함 관련 테스트 24건, TypeScript typecheck, 변경 파일 ESLint가 통과했다.
- PR CI와 동일한 Inventory Stock Control 회귀 묶음 94건도 로컬에서 전부 통과했다.
- 로컬 Next API `/api/shopling-stock-state-sync/download-hf37?verify=1`이 HTTP 200과 `v0.6.5`, 빈 A4 날짜 지원, 모호 시 무변경, HF36 프레임 보호 유지를 반환했다.
- 생성 ZIP의 manifest 버전, HF37 날짜 패치, HF36 background 보존을 직접 확인했다.
- 새 회귀 테스트는 `inventory-stock-control-ci.yml`과 `shopling-stock-state-sync-ci.yml`에 등록했다. 최신 PR head의 CI 통과는 PR 생성 후 확인해야 한다.
- 저장소 전체 `npm test`는 이번 변경과 무관한 기존 환경·모듈·테스트 실패가 있어 통과하지 않았다.

## 남은 운영 검증

1. PR CI가 최신 head에서 통과한 뒤 배포한다.
2. 운영 Chrome에서 확장을 `v0.6.5`로 교체하고 Commerce OS와 Shopling을 새로고침한다.
3. `BBB4-3` 한 건만 다시 실행한다. 이전 실패는 검색 전 무변경이므로 이 단건 재검증은 중복 상태 변경 위험이 없다.
4. A4 기간이 `20230101 ~ 오늘`로 설정되고, A6 품절과 필요한 A21 전송이 성공하며, Commerce OS 결과 상자에 `작업 종료 · 성공 / Shopling 반영: 완료`가 표시되는지 확인한다.
5. 이 단건 검증을 통과하기 전에는 나머지 대기건 전체 자동처리를 재개하지 않는다.
