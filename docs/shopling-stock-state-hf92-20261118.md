# Shopling 재고상태 HF92 — 정확 팝업 영수증과 파란 전송 직접 인계

## 실제 근거

- HF91은 여러 B코드를 확장 프로그램에 동시에 넘기지 않았다. 각 B코드는 한 건씩 순서대로 시작됐다.
- `BDE7-1`은 `HF89_EXACT_POPUP_COMMIT_TIMEOUT`으로 끝났다. 빨간 `상품 수정전송` 뒤 정확한 새 팝업은 열렸지만 그 팝업의 파란 전송 완료 영수증을 제한시간 안에 확인하지 못했다.
- `BDE7-2`는 `HF86_TRUSTED_CLICK_DISPATCH_FAILED`와 `Detached while handling command.`로 끝났다. Chrome이 빨간 버튼 클릭을 처리하는 도중 원래 A21 목록 탭과의 제어 연결이 끊겼다.

## 원인

두 실패는 다건 동시 실행이 아니라 한 건 내부의 팝업 인계 경계에서 발생했다.

1. Chrome 제어 연결이 끊기면 실제 팝업이 이미 열렸는지 확인하지 않고 즉시 클릭 실패로 판정했다.
2. 정확한 새 팝업을 확보한 뒤에도 파란 전송은 공유 HF84 스캐너를 다시 기다렸다. 앞선 스캔의 실행 잠금이 남으면 실제 팝업이 있어도 직접 처리하지 못하고 시간초과가 날 수 있었다.

## 변경

- 확장 버전을 `0.6.54`로 올렸다.
- 신뢰 클릭 중 Chrome 제어 연결이 끊겨도 그 클릭 직후 생긴 정확한 Shopling 팝업이 확인되면 클릭 성공으로 이어간다.
- 정확한 팝업과 현재 B코드 소유권을 다시 확인한 뒤, 그 팝업의 모든 프레임을 직접 조사한다.
- 실행 가능한 프레임이 정확히 하나일 때만 원본 Shopling 파란 전송 함수를 직접 실행한다.
- 원본 전송 실행 영수증을 저장하고 `WAIT_A21_RESULT`로 전환한 뒤에만 기존 결과 감시기로 넘긴다.
- 팝업이나 프레임이 없거나 둘 이상이면 외부 전송을 실행하지 않고 정확한 실패 코드로 중단한다.
- 기존 HF91 정책대로 확장 START 한 번에는 B코드 한 건만 들어가며, 그 건이 터미널 상태가 되고 확장이 idle을 응답한 뒤에만 다음 건을 시작한다.

## 자동 검증

- CDP 분리 뒤 정확한 새 팝업이 생긴 경우 성공 영수증으로 복구한다.
- CDP 분리 뒤 팝업이 없으면 재시도 가능한 실패로 남긴다.
- 정확 팝업 직접 인계가 공유 `probeThenCommitHf84()`를 호출하지 않고 프레임 단위 조사·전송을 수행한다.
- v0.6.54 미만 확장은 Commerce OS에서 실행할 수 없다.
- TypeScript, ESLint, Next.js 프로덕션 빌드와 HF92 로컬 ZIP 생성 검증을 통과해야 한다.

## 실운영 판정 기준

1. v0.6.54 설치 후 단일 신규 B코드 한 건으로 먼저 카나리를 실행한다.
2. Shopling 전송 화면과 Commerce OS `전송 접수 완료 1/1건`을 함께 확인한다.
3. 단일 건이 통과한 뒤 두 건을 입력해 내부 START가 한 건씩 발생하고 최종 `2/2건`이 되는지 확인한다.
4. 이미 외부 전송 가능성이 있는 과거 실패 건은 Shopling 상태를 먼저 확인하고 무조건 재실행하지 않는다.
