# 도매꾹 전체 즉시실행 노출 수정

- 문제: `전체 즉시실행`은 로컬 Next 개발화면에서만 보였고, 사용자가 실제로 쓰는 Vercel 화면과 Windows 업무센터에는 진입점이 없었다.
- 변경: localhost 전용 도매꾹 실행 화면(43122)을 별도 예약 작업으로 운영하고, Vercel과 기존 Windows 업무센터에서 이 화면으로 연결한다.
- 안전: 고정된 4계정 설정과 고정 PowerShell 실행기만 순차 호출한다. 다른 사이트의 POST, 토큰 없는 요청, 중복 실행은 차단한다. 실행 전 브라우저 확인을 요구한다.
- 완료 기준: 43122 화면에 4계정과 버튼이 보이고, Vercel/43121에서 진입 가능하며, 실제 연장을 수행하지 않은 상태에서 상태 조회·보안 차단·순차 실행 회귀시험이 통과한다.

## 06:34 전체실행 정지 사고 후속

- 관찰: 화면은 10분 이상 `진행 중`으로 남았고 서버는 뒤늦게 종료됐다. `buzz1237`, `andy80101` 영수증에는 `LOGIN_FORM_MISSING`이 남았다.
- 직접 근거 1: 로그인 URL이 먼저 바뀐 순간에는 폼이 없지만, 이후 같은 Chrome 대상에서 `#formLogin`, `#idInput`, `#pwInput`이 실제로 생성됐다. URL만으로 로그인 화면 준비를 판정한 경쟁 조건이다.
- 직접 근거 2: PowerShell이 시작한 Chrome이 stdout/stderr 파이프를 계속 소유해 PowerShell 종료 뒤에도 Node의 child `close` 이벤트가 늦어졌다. 계정별 영수증은 먼저 기록됐지만 제어 화면은 180초 제한까지 기다렸다.
- 변경: 로그인 폼 준비까지 기다리고, 래퍼 완료는 PowerShell `exit`로 판정한다. 제어 상태에 현재 계정·완료 수·최근 전체 결과를 포함하고 화면은 1초마다 다시 읽어 새로고침/응답 유실 뒤에도 복구한다.
- 안전: 이번 수정 검증에서는 실제 기간연장을 재실행하지 않는다. 먼저 시험 실행으로 각 계정의 로그인·기간종료 목록을 읽고, 실제 재실행은 현재 상품 상태가 확인된 뒤 별도 사용자 동작으로 남긴다.

## 2026-11-14 운영 화면 비밀번호 갱신

- 오늘 `everysale999`, `andy80101` 실패 코드는 비밀번호 불일치가 아니라 로그인 폼이 늦게 나타난 `LOGIN_FORM_MISSING`이다. 해당 실행에서는 비밀번호 제출 단계까지 도달하지 않아 비밀번호가 맞는지는 판정할 수 없다.
- Vercel 운영 화면의 비밀번호 칸을 활성화하고 계정별 `이 PC에 저장` 버튼을 추가한다. 비밀번호는 Vercel API가 아니라 `127.0.0.1:43122`의 로컬 제어기로 직접 전달하며 Windows 현재 사용자 DPAPI 저장 스크립트의 표준입력으로만 넘긴다.
- 로컬 제어기는 고정 운영 출처와 저장된 계정만 허용하고, 다른 사이트·미등록 계정·과대 요청을 차단한다. 응답과 명령행에는 비밀번호를 포함하지 않는다.
- 직접 근거: 2026-11-14 예약 작업 네 개는 모두 구버전 `commerce-os-domeggook-period-extension-prod-1716` 경로를 실행하고 있었다. 00:10 `everysale999`와 00:25 `andy80101`의 작업 결과는 1, 나머지는 0이었다. 로그인 폼 대기 수정본 배포 후 네 예약 경로를 같은 검증 커밋으로 다시 고정한다.
