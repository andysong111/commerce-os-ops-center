# 온돌패스 신청서 번호 자동 가져오기 — 2026-11-19

## 목표

발주차시 3단계에서 사용자가 온돌패스 신청서 번호만 입력하면 제품정보와 상품 이미지를 읽어 `/freight-barcode-request`의 기존 파서·이미지 매칭을 실행한다. 수동 복사·붙여넣기는 장애 시 대체 경로로 유지한다.

## 확인한 실제 구조

- 실제 신청서 `673626`의 상세 주소는 `/order/order_view.php?order_no=673626`이다.
- 상품은 `div_item_1`부터 `div_item_9`까지 독립 블록으로 존재했다.
- 각 블록에 품목, 옵션, 1688 링크, HS 코드, 단가, 수량, 트래킹번호, 오픈마켓 주문번호, 상품 이미지가 있었다.
- 수취인 정보는 상품 블록 밖에 있으므로 문서 전체가 아니라 정확한 상품 블록만 읽는다.

## 구현 구조

입력 → Commerce OS가 버전이 고정된 메시지를 확장에 전달 → 확장이 로그인된 Chrome에서 정확한 신청서 상세 탭을 열거나 재사용 → 상품 블록만 추출 → 신청번호·URL·행 번호·품목 수를 검증 → 기존 신청서 파서와 이미지 매칭 → 화면에 자동 적용.

확장은 조회 전용이다. 온돌패스 버튼·체크박스·폼을 클릭하지 않고, 쿠키 권한·네트워크 요청 권한·페이지 데이터 변경 코드를 두지 않는다. 확장이 새로 만든 탭만 성공 또는 일반 오류 뒤 닫고, 로그인으로 이동된 탭은 사용자가 로그인할 수 있도록 남긴다.

## 실패 차단 조건

- 신청번호가 숫자 4~20자리가 아님
- 요청 번호, 주소의 `order_no`, 화면의 신청번호 중 하나라도 다름
- 온돌패스 로그인 만료 또는 상세페이지 접근 실패
- 제품 블록 없음, 중복 행, 500개 초과, 비정상적으로 긴 본문
- 제품 블록에 수취인 정보·세부주소·휴대전화 라벨이 섞임
- 추출 품목 수와 기존 파서 결과 품목 수가 다름

실패 시 현재 작업 내용을 덮어쓰지 않는다.

## 검증 계획과 완료 기준

- 순수 검증기, 실제 파서 연결, 행별 이미지 연결, 개인정보 차단을 자동 테스트한다.
- 확장 manifest가 `tabs` 외 권한을 요구하지 않고 스크립트에 클릭·쿠키·별도 fetch가 없음을 회귀 테스트한다.
- ZIP 다운로드의 파일 구성과 캐시 방지 헤더를 테스트한다.
- 기존 신청서 파서·리치 붙여넣기 테스트, lint, typecheck, production build를 함께 통과시킨다.
- 최종 운영 확인은 Chrome에 확장을 설치한 뒤 실제 신청서 1건에서 온돌패스 품목 수와 Commerce OS 분석 품목 수가 정확히 일치하는지 확인한다.

## 현재 검증 결과

- 신규 자동 가져오기 7개와 기존 파서·이미지 회귀를 합친 자동 테스트 41개 통과
- 확장 스크립트 4개 문법 검사 통과

- 운영 Chrome 확장 설치와 실제 신청서 자동 가져오기 1건은 배포 후 사용자 확인이 필요한 최종 단계로 남김
