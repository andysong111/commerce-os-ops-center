# Shopling 재고상태 재전송 사고 기록 — 2026-11-02

## 책임 경계

- Commerce OS 책임: 사용자가 지시한 각 B코드의 판매중·품절 전환을 Shopling에 빠짐없이 전달하고, 현재 B코드가 소유한 Shopling 처리중/결과 화면이 시작된 증거를 Commerce OS 원장에 저장한다.
- Shopling 책임: Shopling이 각 마켓으로 보낸 뒤 마켓이 반환한 성공·실패 결과와 실제 마켓 반영.
- 마켓별 최종 완료·실패는 기다리지 않는다. 정확한 현재 작업의 Shopling 처리중/결과 화면 시작이 확인되면 Commerce OS→Shopling 전달 완료로 기록한다.

## 확인된 원인

1. 최초 BCG5-2·BCG5-3 실패는 Shopling 로그인 만료 상태에서 시작해 Shopling 쓰기 전에 종료됐다.
2. 2-Lane 배치에서 Lane 1 완료와 Lane 2 시작 사이에 MV3 서비스워커가 절전되면, 단일 작업에 묶인 기존 watchdog이 이미 해제되어 Lane 2 시작을 깨울 이벤트가 없었다.
3. BBD8-1 Lane 2는 Shopling 최종 footer `상품상태 변경 전송이 완료되었습니다.`와 결과 108건(성공 83·실패 25)을 표시했지만, 옵션 결과 관찰기가 이 공용 footer를 옵션 완료로 분류하지 않아 Commerce OS 원장에는 STARTED가 남았다.
4. BBA7-1 재전송 때 구버전 확장이 남긴 이름 있는 A21 팝업을 새 작업의 팝업으로 재사용해, 실제 결과 페이지까지 도달하고도 새 작업 소유권 확인에 실패했다.
5. BCC2-1 재전송 사전점검 때 Chrome에 남아 있던 Shopling 탭 20여 개를 한 개씩 순차 검사했다. Commerce OS의 7초 제한 안에 응답하지 못해 Shopling 쓰기나 `STARTED` 기록 전에 안전 중단됐다.

- v0.6.25/HF62 A6 재로딩 복구·전체 B코드 계속 처리:
  - 2026-11-04 실제 23건 실행은 첫 B코드 `BCC3-2`의 A6 조회 화면이 재로딩된 뒤 `0/23`에서 중단됐다. Shopling은 검색 제출 뒤 검색항목·검색어·날짜 입력값을 초기화하는데, v0.6.24는 화면에 입력값이 그대로 남아 있을 때만 이전 제출을 재개로 인정했다. 따라서 같은 검색을 다시 준비하거나 결과행을 기다리다 시간초과했고, 일반 `updatedAt` 저장이 watchdog 활동으로 계산되어 실제 진행이 없어도 고착될 수 있었다.
  - HF62는 `jobId + executionId + stage + 화면경로 + 검색항목 + B코드`의 정확한 제출표를 세션에 저장한다. 같은 실행의 제출표가 있으면 화면 입력값이 초기화되어도 검색 버튼을 다시 누르지 않고 결과행만 최대 20초 기다린다. 다른 실행·다른 B코드에는 제출표를 재사용하지 않는다.
