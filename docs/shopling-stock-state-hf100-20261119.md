# Shopling stock-state HF100 — 초기 팝업 소유권 재확인

## 실제 사건

- 사용자가 손대지 않은 실제 4건 실행에서 품절 2건과 판매중 1건은 Shopling 전송 접수까지 도달했다.
- 마지막 `BCC5-2` 판매중 건은 정확한 A21 상품수정 팝업과 선택 행이 열렸지만, 파란 `상품수정 송신` 버튼은 눌리지 않았다.
- Commerce OS 결과는 `HF92_EXACT_POPUP_OWNER_MISMATCH`, 단계 `A21_LIST`, 성공 3/4로 남았다. 따라서 이 건에는 외부 Shopling 전송 접수 영수증이 없고, 마켓 후속 처리 실패도 아니다.

## 원인

- HF90은 빨간 목록 전송 뒤 열린 정확한 팝업에 job, execution, 상품종류, goods-key 묶음, A21 목록창, 팝업 탭을 묶은 영수증을 먼저 저장했다.
- 직후 같은 B코드 할당이 한 번 더 준비되면서 이미 열린 정상 팝업 ID가 새 `baselineTabIds`에 포함됐다.
- 최종 파란 전송 직전에는 HF96의 신선한 영수증 복구 검사가 있었지만, 그보다 앞선 HF92 초기 검사에는 같은 복구가 없었다. 그 결과 정확한 현재 팝업이 타 작업 팝업으로 오판되어 파란 버튼 전에 안전 중단됐다.
- 품절과 판매중을 한 번에 입력한 것, 판매종료(E) 제외 정책, 옵션/단품 혼합은 직접 원인이 아니다.

## 수정 경계

- HF100 v0.6.60은 초기 파란 전송 소유권 검사에서도 HF96의 동일 작업 증명기를 재사용한다.
- 현재 jobId, executionId, 상품종류, 정규화된 goods-key 묶음, A21 목록 탭, 팝업 탭, opener, assignment가 모두 일치하고 신선한 HF90 `외부 쓰기 전` 영수증이 있을 때만 같은 작업의 재준비를 복구한다.
- 복구 후에도 원본 파란 Shopling 전송 함수는 정확히 한 번만 실행하고, 기존 최종 소유권 검사를 다시 통과해야 한다.
- 영수증 누락, 다른 팝업, 다른 목록창, goods-key 변경은 `HF100_EXACT_POPUP_INITIAL_OWNER_MISMATCH`로 외부 전송 0회 차단한다.
- B코드 한 건씩 직렬 실행, 판매종료(E) API/A21 제외, 원본 전송 접수 시 Commerce OS 책임 완료 정책은 그대로 유지한다.

## 자동 검증

- 실제 `BCC5-2` 화면의 옵션 goods-key 묶음을 회귀 fixture로 고정했다.
- 같은 작업 재준비 + 신선한 정확 영수증: 파란 전송 commit 1회, `WAIT_A21_RESULT` 진입.
- 평상시 정확 팝업: 기존 동작과 동일하게 commit 1회.
- 영수증 누락, 다른 팝업 영수증, goods-key 변경: commit 0회.
- HF99 판매종료 제외, HF98 상세 실패 설명, HF97 접수 책임 경계, HF96 최종 소유권 복구, IDLE 장벽, 직렬 실행 회귀를 함께 검사한다.
- 변경된 현재 운영 회귀 42개 파일의 189개 테스트, TypeScript, 변경 파일 ESLint, 126개 페이지 Next.js 프로덕션 빌드가 통과했다.
- 로컬 빌드 서버 검증 응답은 v0.6.60, ZIP 275,208 bytes였다. ZIP SHA-256은 `e021f2d67dd43281995f7b499cfe0a34b579def698203b94eea6e7c42c3a0eb3`, 패치된 background SHA-256은 `0840fd6528fdf7f626f27bb613cb81e918f7e1f262ec8faeeb2f310aa9b9019f`다.
- 실제 Shopling 운영 성공은 배포 후 v0.6.60을 설치하고 미전송 `BCC5-2` 한 건만 카나리 재실행해 원본 접수 영수증을 확인하기 전까지 확정하지 않는다.

## 운영 카나리

1. 종결된 기존 실행의 열려 있는 미전송 A21 팝업을 닫는다. 파란 버튼은 수동으로 누르지 않는다.
2. Commerce OS에서 v0.6.60 ZIP을 받아 기존 확장 폴더를 교체하고 Chrome 확장 화면에서 다시 로드한다.
3. Shopling 로그인과 Commerce OS `자동화 연결됨 · v0.6.60`을 확인한다.
4. 미전송 `BCC5-2` 한 건만 다시 실행한다.
5. Commerce OS의 `전송 접수 성공` 영수증과 Shopling 결과 화면 진입을 확인한다. 이후에만 다건 실행을 재개한다.
