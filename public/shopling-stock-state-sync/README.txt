Commerce OS · Shopling Stock State Sync v0.4.1

사용자 준비
- Stock State Sync 구버전은 모두 제거/비활성화하고 v0.4.1 하나만 사용합니다.
- Shopling에 로그인 완료한 관리자 메인 탭 하나와 Commerce OS 재고·품절·재입고 탭만 열어둡니다.
- 로그인 폼만 열린 상태는 실행할 수 없습니다.
- A4/A21은 미리 열 필요가 없습니다. 실행 시 필요한 전용 작업창만 자동 생성합니다.
- 옵션상품은 A6 작업창을 생성하지 않습니다.
- 원본 관리자 탭은 새로고침하거나 이동하지 않습니다.
- 재고 0 기준점은 다시 만들지 않고 1건 안전 실행만 합니다.

실행
- 옵션: Commerce OS 서버 → Shopling 상품조회 API에서 후보 goods key와 B코드 옵션을 정확 1건 검증 → Shopling 현재 optQty를 그대로 보존 → optStatus만 판매중(B)/품절(C)로 변경 → API 응답과 재조회 검증 → 자동 생성 A21 → API로 확정한 goods key 정확검색 → 옵션송신.
- 단품: 자동 생성 A4 → goods key 정확검색 → 상품상태 품절/판매중 → 자동 생성 A21 → 상품판매상태송신.
- A22 및 마켓 재고수량 동기화는 사용하지 않습니다.
- 단품 A4와 A21 검색기간은 2024-01-01~실행 당일(한국 시간)이며 실제 입력값을 검증합니다.
- 실패·결과불확실 작업창은 확인을 위해 그대로 둡니다. 최종 A21 결과 확인 전 성공 처리하지 않습니다.

v0.4.1 A21 검색 안전장치
- A21 화면에 '샵플링상품코드'가 들어간 드롭다운이 여러 개 있어도 실제 '검색항목' 행의 드롭다운만 점수화해 선택합니다.
- 검색어 입력칸은 선택된 검색항목 드롭다운과 같은 행 안에서만 찾습니다. 상단 전역 검색창으로 대체하지 않습니다.
- 검색 버튼을 누르기 직전에 선택값이 '샵플링상품코드'인지, 검색어가 API 확정 goods key와 정확히 같은지 다시 검증합니다.
- 결합 검증이 실패하면 SEARCH_BINDING_MISMATCH로 중단하고 검색 버튼 자체를 누르지 않습니다.
- 검색 제출 티켓은 Shopling이 같은 문서에서 AJAX 갱신을 하더라도 유지되어 동일 작업에서 검색 버튼을 두 번 누르지 않습니다.
- 결과 행을 연결하지 못하거나 결과가 없으면 재검색 루프 대신 실패로 종료합니다.

v0.4.0 옵션상품 구조 변경
- A6 레거시 표는 정확 1건 검색 후에도 행·체크박스·드롭다운 연결이 불안정해 옵션상품 자동화 경로에서 제거했습니다.
- Shopling API에서 optPtnOptCd가 B코드와 정확히 일치하는 옵션이 1건일 때만 변경합니다. 0건 또는 2건 이상이면 안전상 중단합니다.
- 옵션상태는 B(판매)↔C(품절)만 자동 전환합니다. X(미사용)는 자동 복구하지 않습니다.
- 옵션 수정 API가 optQty를 필수로 요구하므로 Commerce OS 재고를 보내지 않고 Shopling에서 읽은 현재 optQty를 그대로 재전송합니다.
- 수정 응답 code=000, 성공 1건, 실패 0건을 확인한 뒤 같은 옵션을 다시 조회해 목표상태와 optQty 불변을 확인합니다.
- API 검증이 끝난 goods key 1건만 A21에 전달합니다.
- API가 이미 목표상태라면 로컬 변경은 생략하고 상태를 검증한 뒤 A21만 실행합니다.
- API 성공 후 A21이 실패하면 A21만 재시도하도록 설계합니다.

구현/배포
- Shopling API 인증정보는 Commerce OS 서버 환경변수에서만 사용하며 확장프로그램에 포함하지 않습니다.
- A21은 기존 가격조정 확장에서 검증한 새 작업창 생성 + background all-frame 직접탐색 패턴을 재사용합니다. 가격 확장 자체는 수정하지 않았습니다.
- 단품 A4/A21 및 옵션 A21은 content-shopling-v030.js 작업엔진을 사용합니다.
- 재고·발주·취소·반품 데이터와 계산 로직은 수정하지 않습니다.
