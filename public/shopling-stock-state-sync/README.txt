Commerce OS · Shopling Stock State Sync v0.4.3

사용자 준비
- Stock State Sync 구버전은 모두 제거/비활성화하고 v0.4.3 하나만 사용합니다.
- Shopling에 로그인 완료한 관리자 메인 탭 하나와 Commerce OS 재고·품절·재입고 탭만 열어둡니다.
- 로그인 폼만 열린 상태는 실행할 수 없습니다.
- A4/A21은 미리 열 필요가 없습니다. 실행 시 필요한 전용 작업창만 자동 생성합니다.
- 옵션상품은 A6 작업창을 생성하지 않습니다.
- 원본 관리자 탭은 새로고침하거나 이동하지 않습니다.
- 재고 0 기준점은 다시 만들지 않고 1건 안전 실행만 합니다.

실행
- 옵션: Commerce OS 서버 → Shopling 상품조회 API에서 후보 goods key와 B코드 옵션을 정확 1건 검증 → Shopling 현재 optQty를 그대로 보존 → optStatus만 판매중(B)/품절(C)로 변경 → API 응답과 재조회 검증 → 자동 생성 A21 → API로 확정한 goods key 정확검색 → 해당 goods key의 쇼핑몰 결과행 전체 선택(최대 200건) → 수정전송 팝업에서 옵션송신 단독 설정 → 옵션송신.
- 단품: 자동 생성 A4 → goods key 정확검색 → 상품상태 품절/판매중 → 자동 생성 A21 → 상품판매상태송신.
- A22 및 마켓 재고수량 동기화는 사용하지 않습니다.
- 단품 A4와 A21 검색기간은 2024-01-01~실행 당일(한국 시간)이며 실제 입력값을 검증합니다.
- 실패·결과불확실 작업창은 확인을 위해 그대로 둡니다. 최종 A21 결과 확인 전 성공 처리하지 않습니다.

v0.4.3 A21 수정전송 팝업 규칙
- 목록용 content-shopling-v030.js는 goods_mallMdfy_trsmt.phtml 팝업에서 실행하지 않고, 전용 content-a21-popup-v043.js가 팝업만 담당합니다.
- 기존 가격수정 확장에서 검증된 configureOptionPopup 원리를 그대로 사용합니다.
- 상단 '옵션송신' 모드를 먼저 선택합니다.
- 하단 옵션송신 행의 '선택' 컨트롤을 별도로 선택합니다.
- '추가상품송신' 및 '옵션+추가상품송신' 체크가 있으면 해제합니다.
- 상단 옵션송신과 하단 선택이 모두 유지되고 금지된 추가상품 체크가 0건인지 재검증한 뒤에만 '상품수정 송신'을 클릭합니다.
- 단품은 같은 전용 팝업 worker에서 '상품판매상태송신'과 목표상태(품절/판매중)를 검증한 뒤 전송합니다.
- 전송 후 결과화면의 처리중/완료/실패 증거를 계속 Commerce OS background에 전달합니다.

v0.4.2 A21 다건 선택 규칙
- A21은 Shopling goods key 1개를 정확 검색하면 여러 쇼핑몰 상품행이 나오는 것이 정상입니다.
- 화면출력을 200개로 맞춘 뒤 조회결과가 1~200건이면 모든 행이 같은 goods key인지 검증하고 정확 일치 행 전체를 선택합니다.
- 조회건수와 정확 goods key 행 수가 다르면 다른 상품이 섞인 것으로 보고 전송하지 않습니다.
- 200건을 초과하면 일부만 보내지 않고 A21_RESULT_OVER_200_BATCH_LIMIT으로 안전 중단합니다. 200건 초과 자동 페이지 배치는 별도 검증 후 확장합니다.
- 기존의 'A21 정확 1행' 제약은 제거했지만, 검색 goods key 자체는 서버 API에서 여전히 정확 1건으로 확정된 값만 사용합니다.

v0.4.1 A21 검색 안전장치
- A21 화면에 '샵플링상품코드'가 들어간 드롭다운이 여러 개 있어도 실제 '검색항목' 행의 드롭다운만 점수화해 선택합니다.
- 검색어 입력칸은 선택된 검색항목 드롭다운과 같은 행 안에서만 찾습니다. 상단 전역 검색창으로 대체하지 않습니다.
- 검색 버튼을 누르기 직전에 선택값이 '샵플링상품코드'인지, 검색어가 API 확정 goods key와 정확히 같은지 다시 검증합니다.
- 결합 검증이 실패하면 SEARCH_BINDING_MISMATCH로 중단하고 검색 버튼 자체를 누르지 않습니다.
- 검색 제출 티켓은 Shopling이 같은 문서에서 AJAX 갱신을 하더라도 유지되어 동일 작업에서 검색 버튼을 두 번 누르지 않습니다.
- 결과 행을 연결하지 못하거나 결과가 없으면 재검색 루프 대신 실패로 종료합니다.

v0.4.0 옵션상품 구조 변경
- A6 레거시 표는 정확 1건 검색 후에도 행·체크박스·드롭다운 연결이 불안정해 옵션상품 자동화 경로에서 제거했습니다.
- Shopling API에서 optPtnOptCd가 B코드와 정확히 일치하는 옵션이 1건일 때만 변경합니다. 0건 또는 2건 이상이면 안전상 중단합니다.
- 옵션상태는 B(판매)↔C(품절)만 자동 전환합니다. X(미사용)는 자동 복구하지 않습니다.
- 옵션 수정 API가 optQty를 필수로 요구하므로 Commerce OS 재고를 보내지 않고 Shopling에서 읽은 현재 optQty를 그대로 재전송합니다.
- 수정 응답 code=000, 성공 1건, 실패 0건을 확인한 뒤 같은 옵션을 다시 조회해 목표상태와 optQty 불변을 확인합니다.
- API 검증이 끝난 goods key 1건만 A21에 전달합니다.
- API가 이미 목표상태라면 로컬 변경은 생략하고 상태를 검증한 뒤 A21만 실행합니다.
- API 성공 후 A21이 실패하면 A21만 재시도하도록 설계합니다.

구현/배포
- Shopling API 인증정보는 Commerce OS 서버 환경변수에서만 사용하며 확장프로그램에 포함하지 않습니다.
- A21 목록은 기존 가격조정 확장에서 검증한 새 작업창 생성 + background all-frame 직접탐색 패턴을 재사용합니다.
- A21 수정전송 팝업은 가격조정 확장의 상단 모드 + 하단 선택 + 추가상품 해제 검증 패턴을 전용 worker로 분리해 재사용합니다.
- 가격조정 확장 자체는 수정하지 않았습니다.
- 재고·발주·취소·반품 데이터와 계산 로직은 수정하지 않습니다.
