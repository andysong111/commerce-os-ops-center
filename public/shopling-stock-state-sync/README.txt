Commerce OS · Shopling Stock State Sync v0.5.5 HF3

사용자 준비
- 이전 Stock State Sync 확장은 제거/비활성화하고 현재 v0.5.5 HF3 패키지 하나만 사용합니다.
- Shopling 로그인 관리자 탭 하나와 Commerce OS 재고·품절·재입고 탭을 열어둡니다.
- A4/A6/A21은 미리 열 필요가 없습니다. 실행 시 전용 작업창을 자동 생성합니다.
- 재고 0 기준점은 다시 만들지 않고 1건 안전 실행만 합니다.

옵션상품 실행
- A6 옵션대량수정 자동 진입.
- 검색기간 2013-09-12~실행 당일(KST).
- 검색항목 `옵션자체관리코드`에 실행 B코드를 정확 검색.
- A6에서는 결과행을 체크하거나 상태변경하지 않습니다. 검색결과의 textContent와 input/textarea/select 현재값을 읽어 정확 B코드 행을 확인합니다.
- 정확 B코드 행의 `상품코드-옵션코드`에서 Shopling 상품코드(goods key)만 전부 수집·중복 제거합니다.
- 확보한 goods key를 하나씩 Commerce OS Shopling API에 보내 해당 B코드 옵션상태만 품절/판매중으로 검증·변경합니다. Shopling 현재 옵션수량은 그대로 보존합니다.
- 모든 goods key의 API 검증이 끝나면 A21에서 1/N → 2/N → ... 순서로 직렬 옵션송신합니다.
- 모든 goods key가 완료되어야 B코드 전체를 성공으로 처리합니다.

A21 목록 경로
- A21 goods key 검색결과의 정확 일치 쇼핑몰 행을 최대 200건까지 선택합니다.
- Shopling이 `총 조회수` 문구를 제공하면 그 값을 우선 검증하고, 문구가 없으면 현재 화면의 정확 goods key 행 수를 사용합니다.
- `상품 수정전송`은 가격조정 확장프로그램의 검증된 A21 직접 클릭 규칙을 기준으로 사용합니다. 현재 frame에서 찾지 못하면 동일 Shopling 창에서 접근 가능한 top/child frame 전체를 순회하고 button/input/a/onclick 및 레거시 이미지 alt/title을 함께 읽어 실제 클릭 가능한 요소를 찾습니다.
- 수정전송 팝업이 열리면 가격조정 확장프로그램의 검증된 PriceCore를 그대로 사용해 `옵션송신`만 선택하고 Shopling MAIN-world 원본 송신 함수를 호출합니다.
- 총건수 문구가 없고 정확행이 200건에 도달하면 다음 페이지 존재 가능성을 배제할 수 없어 부분전송하지 않고 중단합니다.

단품상품 실행
- A4에서 goods key 정확 검색 → 상품상태 품절/판매중 변경 → A21 상품판매상태송신.

A21 안전장치
- A6의 체크박스/상태 일괄변경은 사용하지 않습니다.
- Shopling 자체 수정전송 완료가 확인되면 쇼핑몰별 개별 실패는 증거로 기록하고 다음 goods key로 진행합니다.
- A22 및 마켓 숫자 재고수량 동기화는 사용하지 않습니다.
